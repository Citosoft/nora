# Nora: Product Vision & Design Brief

## Overview

**Nora is a universal AI-powered work environment that adapts to the individual, their role, their tools and the way they prefer to work.**

Rather than forcing users into predefined software interfaces, Nora allows them to shape their own experience through natural conversation.

Nora should be suitable for anyone, from developers and designers to salespeople, accountants and HR professionals.

The goal is to make Nora the primary place people go to get work done, bringing AI capabilities and their existing business applications into one unified experience.

## Core Experience

### 1. AI-first conversational interface

Chat remains a fundamental part of Nora.

Users can interact with AI models and agents to complete tasks, ask questions, create content, write code and perform work across connected applications.

Existing developer capabilities, including coding agents, project management and development workflows, must remain first-class features.

The experience should adapt to the user's activities rather than favouring any particular profession.

### 2. Personalised, dynamic workspaces

Users can create fully interactive workspaces simply by describing what they want.

For example:

"Create a customer management workspace showing my HubSpot contacts, outstanding Xero invoices, support tickets and recent customer emails."

Nora generates a functioning interface combining these applications, allowing users to view information and perform actions without switching between tools.

These should feel like real applications, with interactive tables, dashboards, forms, buttons, charts and other relevant components, not static AI-generated content.

### 3. Conversational interface design

Users should be able to modify generated workspaces through natural language.

For example:

"Move the invoices to the right, make the customer information more prominent and add a button to create a support ticket."

Nora updates the existing interface rather than rebuilding everything unnecessarily.

The aim is to give users control over how their software works without requiring programming knowledge.

### 4. Multiple persistent workspaces

Users can create, name, save and revisit multiple personalised workspaces.

Each workspace can combine different applications and serve a different purpose.

Workspaces should retain their design and configuration while displaying up-to-date information from connected services.

Users should also be able to refine existing workspaces and restore previous versions.

### 5. Deep integration with existing tools

Integrations are fundamental to Nora.

Users should be able to connect their CRM, email, accounting, project management, HR and other applications.

Nora should use these connections to retrieve information, execute permitted actions and combine functionality across multiple systems.

The ultimate ambition is to reduce, or potentially eliminate, the need to open those applications individually.

### 6. Adaptive onboarding and experience

During onboarding, Nora should learn about the user's role, interests and connected applications.

This information helps Nora provide a relevant starting experience without restricting what the user can subsequently do.

A developer may primarily see coding conversations and agent tools, while a salesperson may prefer customer dashboards and sales workflows.

Users should be free to combine both approaches.

## Initial User Journey

1. A user installs Nora and identifies their role or intended use.
2. They connect the applications and AI providers they want to use.
3. Nora presents a relevant starting experience with a familiar conversational interface.
4. The user can immediately start working through chat or request a personalised workspace.
5. Nora generates a usable first version based on their request and available integrations.
6. The user refines the interface conversationally and saves it for future use.
7. They can create additional workspaces while continuing to use Nora's broader AI capabilities.

## Development Priorities

**Phase 1: Core vision**

- Preserve and expand Nora's existing AI chat and agent capabilities.
- Introduce role-aware onboarding and personalisation.
- Support connections to external applications.
- Enable conversational generation and refinement of interactive workspaces.
- Allow multiple saved, persistent workspaces.
- Support real actions within connected applications, respecting existing permissions.
- Keep the experience responsive, consistent and approachable for non-technical users.

**Future phases**

- Direct visual editing, including drag-and-drop and resizing.
- Sharing workspaces with colleagues.
- Organisation-wide workspace templates and collaboration.
- More advanced AI-driven personalisation and automation.

## Guiding Principle

Nora should not become another complicated application users have to learn.

It should provide a flexible environment in which AI, connected applications and personalised interfaces work together naturally.

The application should feel alive, adapting to what users want to accomplish while maintaining a familiar, reliable foundation.

**The user shouldn't have to adapt to their software. Their software should adapt to them.**

The development agent should determine the most appropriate technical implementation, prioritising a secure, reliable and extensible foundation that supports this long-term vision.
