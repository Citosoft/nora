### Features

- Type # in a thread prompt to search and select open workspace issues by number or title, inserting a GitHub or GitLab issue reference.

- Add an Issues workspace tool with search, sorting, expandable descriptions and direct access to the full issue viewer for GitHub and GitLab.

- Install the bundled Nora skill from Settings → Skills and hand tasks to agents by stable ID, with built-in tools to read, start, reopen and finish tasks while keeping completion status and board columns in sync.

- Browse workspace MRs and pull requests in an edge-to-edge grouped full-screen table with search, sorting, expandable descriptions and changed-file previews, sidebar pinning, and access to the existing full-screen review viewer.

- Change your work role from Settings → General using the original role picker, with your current choice selected, custom roles, and Save or Cancel controls; existing conversations keep their role.

- Let Nora agents read and change any app setting through built-in get_settings and update_settings tools, including theme, appearance, integrations, AI, voice and thread defaults, with changes saved and reflected immediately in Settings.

- Get a desktop notification when any thread or bot, including an asked bot or a group member working in the background, is waiting for your approval or answer, with the Dock badge counting what's waiting; clicking the notification opens that thread, a thread whose bot is waiting shows it on its sidebar row with a shortcut to the waiting thread, and while Nora is open, requests from other threads gather in a compact tray in the bottom-right corner, which collapses to a "waiting" pill, where you can allow, decline or answer them without switching threads.
- Sync appearance, general preferences and thread defaults across signed-in devices with opt-in controls, saved-format migration, offline retries and per-setting merges; credentials and workspace data stay local.
- Sign in, manage your profile and sign out from the sidebar avatar using compact Clerk dialogs styled to match Nora’s controls and theme, with encrypted session storage and optional local-only use.
- Show a compact user avatar at the bottom of the Threads/Bots strip, using your name's initial with a user icon fallback and a larger click target.
- Create bots with a name, role, instructions, model and an animated blob avatar, everywhere or per workspace (private, or shared with collaborators as `.nora/bots` files), and message them from the Bots sidebar; the threads bots work in keep the instructions they started with and show the bot's face in the sidebar. Switch the sidebar between Threads and Bots from a vertical strip beside it to browse workspace and global bots and see the threads each one works in. A bot's work thread switched to another model offers a one-click way back to the bot's model.
- Ask Nora, now listed first in the Bots sidebar as your built-in app assistant, to create bots for you from any thread with Claude, Codex or ACP agents that support HTTP MCP servers; Nora's built-in server and its tools are listed first in MCP Servers settings with whether it is running.
- Nora threads can now update bots, list workspaces and each provider's models, list and read other threads, and list, create and move tasks on the workspace task board, all through Nora's built-in tools.
- Let Nora and bots ask other bots for help with ask_bot (including when you @mention a bot to Nora, with bots suggested as you type @): the asked bot answers in its own read-only child thread with its own model, each ask shows as a card with the reply and a link to that thread, and chains of bots asking bots are limited and cannot loop.
- Give Nora and bots memory that carries across threads: they save durable notes with remember, correct or merge them and forget stale ones, find them with full-text recall search, their newest notes are added to new turns as context (with a pointer to recall when older ones don't fit), bots can list and read their own earlier threads to pick up past work, and you can see, add, edit and delete notes in each bot's settings or info panel, including Nora's.
- Nora and bots now learn from their threads automatically: when a thread goes quiet, is settled or reaches 10 turns, a background review saves lasting preferences and facts, corrects outdated notes and shows them as "Saved automatically", never changing notes you wrote. Choose its own source and model (Claude or Codex runtime, or Cloud API) under Memory in Settings → Bots, turn it off there, and see what each review changed and how many tokens it used over the last 7 days.
- Start group chats with 2–6 bots from the Bots sidebar: @mentioned members (suggested as you type @ in the composer) (or the ones Nora picks) reply one at a time in the group from their own threads, can hand off to each other by @mention, and only the member you choose can change files.
- Chat with each bot in one persistent direct message, and with groups, in a messages-only chat: replies arrive as chat bubbles with a typing line while the bot works, approvals and questions appear as cards in the chat, each new task runs in its own work thread (in whichever workspace you choose under "Working in", or the one the message names) and every reply links to the work behind it with View work.
- Give group chats an optional lead who answers messages Nora can't match to a member, ask every member at once with @everyone, and let members read earlier group messages with a new chat_history tool instead of losing them from a longer, 40,000-character catch-up.
- Show or hide bots' work threads from Thread view options, the eye button beside Groups in the Bots sidebar, or the one in a chat's header; hidden threads still appear when they need your approval or input.
- Rename groups and threads, or settle and reopen groups, from a right-click menu in the Threads list and the Bots sidebar's Groups section.
- Open a bot's info panel from the info button or right-click menu on its row in the Bots sidebar (which also offers Message, Show work threads and Edit bot) to see its model, availability, instructions, notes, recent work and groups, and message it or edit it from there.
- Delete a bot from its right-click menu or info panel in the Bots sidebar, after a confirmation that warns when a shared bot's file will be removed from the workspace.
- Add a Bots home, opened from the Bots strip, with cards for Nora and each bot (start or continue threads, edit), your group chats, an introduction to bots when you have none, and twelve templates such as Code reviewer, Meeting summariser and Planner that open the bot editor prefilled, with the ones suited to your workspace's role suggested first.
- Budget supported Claude text tool results before model delivery with full local output, diagnostic excerpts and targeted reads, and use Codex's native output ceiling without increasing stricter configured limits; configure this in Threads settings.
- Add a Tool output budget dev simulator scenario with a large synthetic log, a retained error excerpt and a targeted read of its saved output, without using model tokens.
- Restore detected npm, pnpm, and Yarn commands on workspace home in a compact searchable picker with a Run button that opens a workspace-root terminal.
- Add a home button beside the workspace picker to return to workspace home while keeping thread tabs open.
- Change providers or model settings in an idle chat on the next send, preserving visible history and continuing in a fresh session with a bounded handoff and on-demand history reference.
- Add a Switch provider dev simulator scenario with local Codex and Claude sessions, saved handoffs and a simulated on-demand history read, using zero model tokens.
- Attach native chats beside Attach files as dated references with paginated history and bounded text chunks, loading their contents only when the agent reads them.
- Open Threads settings directly from a cog in the chat composer's top-right corner.
- Set a default subagent model for new threads in Threads settings, with per-thread overrides and fallback when the provider or model is unavailable.
- Choose whether follow-up messages queue or steer a supported active turn, preserving delivery confirmation and retry safety.
- Turn automatic thread title generation on or off in Threads settings.
- Automatically move completed, inactive threads to Settled after a configurable period, preserving history and excluding pending work.
- Configure Claude's context compaction threshold in Threads settings while retaining provider defaults when unset.
- Add Threads settings with compaction suggestions for large native chats after estimated cache expiry and opt-in Claude compaction before expiry that skips active work and pending approvals.
- Show native chat cache reuse and reported cache writes in context details, and retain cache reads and writes in provider usage accounting.
- Bound attached archived history to a small selection of intact entries, preserving the full selected context in local files the agent can read on demand.
- Attach images and files to chat by pasting, dropping, or choosing files, with image thumbnails and removable attachments preserved in drafts and delivery retries.

- Settle idle threads to hide them without deleting history, then browse Settled threads and reopen them when needed.
- Discover local Codex and Claude CLI and desktop coding conversations, resume them with saved history and native context.
- Show workspaces together with colorful two-letter avatars and user-selectable colors, plus saved Workspace, Activity, or flat thread grouping in the sidebar.
- Add Claude's Auto permission mode and distinguish Manual, Accept edits, and Plan with descriptions of how approvals work.
- Show Claude's suggested follow-up as ghost text in an empty chat composer, with Tab to accept without sending and a simulator scenario for trying it.
- Add a Stacked approvals simulator scenario that raises three requests together for testing approval, denial, and stopping the task.
- Add a Background requests simulator scenario that raises approvals and questions while you are in another conversation, for trying the in-app request toasts without model tokens.
- Run installed ACP coding agents such as Cursor, OpenCode, Google Antigravity, Grok, Copilot, Goose and Kimi as native thread providers, with their own models and modes, approvals, interrupts, sign-in status and provider icons, connecting agents installed while Nora runs without a restart.

- Show whether Claude and Codex are signed in, with the plan and account, on each provider in Providers settings, and sign in from there through each runtime's browser sign-in.

- Discover MCP servers and tools from Codex and Claude runtimes (ACP agents that do not report MCP status are left out instead of listing a notice for each) in a dedicated MCP Servers settings table showing each server's own logo and provider icon, global or workspace scope, connection status and tools, with refresh, browser sign-in for Codex and Claude servers that need it (including claude.ai connectors) without leaving Nora, and an explanation when Claude account connectors cannot load.

- Show a PR icon with its number and state in the tooltip for sidebar threads linked to a branch pull or merge request, alongside activity and attention indicators.

- Show how full the thread's context window is as a donut beside Send for Claude and Codex, including existing and resumed threads read from saved history, with token details and a Compact context button in a hover popover.
- Show compact stacked toasts in the bottom-left on launch, each with the provider's icon, for every installed provider CLI (Claude Code, Codex, and other npm-distributed agents) that is behind its latest release, with Update and Dismiss buttons; dismissed updates stay available from an icon at the bottom of the sidebar until the next launch.
