### Features

- Bot templates include role-specific routine presets with task and schedule previews; choose which to add during creation, then edit and enable the paused routines when ready.
- Bot templates recommend role-specific connectors, preselect matching available accounts during creation and preview missing services in the catalog; multiple accounts remain your choice.
- Choose connectors in a compact picker beneath bot instructions; saved selections apply to existing work threads on their next turn and appear consistently in connector lists.
- Browse bot templates in a spacious dialog above the app, with search, role filters, personalised suggestions and full responsibility previews before opening the create dialog.
- Expanded the bot template catalog from 12 to 36 roles across engineering, product, design, research, business operations and communications, with tailored responsibilities and role-based suggestions.
- Bots can start and track separate work threads, nested under collapsible chat rows. The DM sidebar groups compact worker rows with model, age, hover settlement and consistent provider icons backed by each thread’s saved subscription/API identity, plus a collapsible Activity timeline.
- A bot's chat sidebar has a Connectors tab beside Activity, listing the connectors that bot gets in the chat's workspace, with a sign-in where one is needed.
- Clicking a thread in a bot chat's Activity sidebar opens it inside the Activity tab: its status, brief, workspace and model, a timeline of each turn (who asked, how it went, tools run and files changed), the latest reply with any questions to answer, and a composer to give it more input, with Back to return.
- Work threads carry what "done" means: a bot starting a worker can state it, a bot's chat writes one for each new task, the thread's agent checks it before reporting back, and the thread's detail in the chat sidebar shows it under Done means.

- Chat threads have a compact prompt history rail on the left: hover a bar to preview its input and last reply, click to jump back, and longer highlighted bars track the turns in view.

- Browse shared apps on the website and open an install review in Nora with a nora:// link, including workspace and connector choices.
- Shared apps carry safe connector setup hints and automatically add missing standard OAuth connectors in the destination workspace, reusing existing connectors and leaving account sign-in to the recipient.
- App panels can be rearranged with a drag handle or arrow keys in the builder and finished app; layouts save automatically as restorable versions.
- Agents can ask for passwords, API keys and tokens through a secure dialog in the chat instead of having them pasted into it: values are encrypted with the system keychain, never reach the transcript or the model, and are used by name in commands you approve, with their output redacted. Settings → Vault lists saved secrets and lets you add, replace or delete them.
- Images agents produce now appear in the thread under the call that made them: Codex image generation, and images Claude writes or delivers, including in imported Claude conversations.
- CSV and TSV files open as a table in the file viewer, with sticky headings, row numbers and right-aligned number columns; a Text toggle switches back to the editor.
- Each workspace has a Library: a sidebar tool showing every image and non-code file agents produced across all of its threads as a grid of thumbnails, with search, filters by type and thread, and grouping by date, thread or type. Selecting one opens it in a viewer over the grid, where the arrow keys step through the rest.
- Thread details now has an Outputs section listing the images and non-code files (documents, spreadsheets, media and archives) the agent produced, including files Claude wrote or delivered outside the checkout. Selecting an output, or an image in the chat, opens it in the file viewer when the viewer can show it, and otherwise in its default app or the file manager.
- Open tasks have a Run workflow menu in the task list: pick one of the workspace's saved workflows to open its run setup with that task as the goal and a branch named after it.
- The mobile app has a Bots section in its sidebar: pick a bot to open its chat or start one, with the bot's avatar and live status. Needs Nora Desktop 2.0.1 or newer on the linked computer.
- An Inbox gathers everything across your workspaces that needs you (approvals, questions, paused workflows and connectors to sign in to) and what finished while you were away, with a preview of each result. Answer requests in place, mark updates read or done, snooze anything, and the Dock badge and notifications follow it. Unread threads now stay unread after Nora restarts, and Nora Remote's Approvals screen becomes the same Inbox (finished work and marks need Nora Desktop 2.0.1 or newer).
- Choose which sections the floating Thread details panel shows: right-click the panel, or use the cog in its header, to hide or show Overview, Subagents, Reviewed changes, Outputs, Branch changes, Connectors, Skills and more. Your choice applies to every thread and is remembered.
- Apps: a new Apps section in the sidebar where you describe a dashboard or mini app ("my HubSpot contacts, open Xero invoices and a button to create a ticket") and Nora builds it over your connectors, live beside the chat that shapes it. Apps show tables, charts, numbers, lists and forms fed by connector tools, refresh on open or on a schedule, and run connector actions from buttons and rows after a confirmation (or without one once you trust the app). Every edit is a version you can restore, and apps stay in the sidebar across restarts.
- Adding a connector starts from a gallery of work tools with official MCP servers (Gmail, Google Calendar, Drive, Docs, Sheets, Slides and Chat, Slack, Notion, Linear, Jira & Confluence, Asana, monday.com, HubSpot, Intercom, Stripe, GitHub, Sentry, Figma and Canva): pick one and Nora fills in its server, points you to the service's setup guide when it needs your own OAuth client, and still lets you add any other MCP server. The gallery is the Add connector flow in Settings, in the chat composer and on the Apps home.
- Each app gets its own icon: the builder picks one that fits what the app is for, shown in the Apps sidebar, the Apps home and the app's header, and it travels with exported app files.
- Apps gain Calendar and Timeline views for anything with a date, Image for pictures a row carries, and Link to open a record in the connected service.
- Apps can page: a source that reads from a paging tool offers Load more on its card and appends the next page (by offset or cursor), and a Table or List can show a page of rows at a time with Show more.
- Apps can read files on your computer: a CSV, TSV or JSON file becomes a source like a connector tool, shows as rows, and the app re-reads it whenever the file changes while it is open.
- Apps say how fresh their data is: each card shows "Updated 2 minutes ago", an app left open reloads stale sources when you come back to the window, and a DateRange input offers presets like Last 7 days (or two dates) that sources can read as arguments.
- Apps keep an activity log: every action an app runs is listed under Activity in its menu with when it ran, what was sent, whether you confirmed it and what the tool replied; the confirm sheet now says plainly what will run, and results that come back as data show as a short summary.
- Apps gain three building blocks: Tabs for tools with several screens, a Kanban board that groups rows by a field and writes a drag between columns back through the connector, and table cells that can be edited in place and saved through an action.
- Point at what to change: in an app's builder, hovering a card shows a Change button that starts the request with that card named, and the builder's suggested next changes appear as one-click chips under the app.
- Apps can be shared as files: Export to file in an app's menu writes its spec with no credentials, and Import from file on the Apps home brings one in, matching each connector it names to yours by server and letting you choose or add the rest.
- Apps can watch for you: a source can keep refreshing in the background while the app is closed, and alerts over its rows ("3 invoices overdue") land in the Inbox with a notification when they become true, open the app when clicked, and clear when the condition passes.
- Apps can open a record: clicking a row in a table or list can select it, a Record component shows the selected item's fields (or a detail source fetched for that selection), and views switch with the selection, so "make the names clickable to see the contact" now works.
- Building an app no longer shows the agent at work: a building scene narrates what Nora is doing ("Looking at your connectors…", "Trying HubSpot…", "Composing your app…") and the finished app slides into view. A bar under the app takes the next change and returns to the scene; the full chat slides in from the right with the Chat toggle, and opens by itself when the agent needs an answer or stops.
- Apps can have filters, searches and date ranges the user controls: a source's arguments can read app state, so an input or dropdown bound to that state reloads the source with the new value (no agent involved), with defaults set by the builder.
- The New app screen now lets you choose which workspace and model build the app and which of the workspace's connectors it may use (with sign-in and Add connector right there); the builder thread only gets the connectors you picked. Example apps fill the description to start from.
- The chat composer remembers what you send: press Up in an empty composer (or with the caret at the start) to step back through previous prompts and Down to return to your draft. Press ⌘S (Ctrl+S) to stash the draft for later and again on an empty composer to bring it back; a stashed-prompts menu under the composer lists everything you've set aside to restore or delete.
- Connect Claude with an Anthropic Console account (API usage billing) as well as a Claude subscription: Sign in for Claude in Settings → Providers now asks which to use, a Switch account option moves a signed-in Claude between the two, and Console sign-ins show as "Anthropic Console".
- Nora can orchestrate a job: it hands each part to a worker thread with its own prompt and a chosen model (or a saved bot), carries on or waits for them to finish, follows up where needed and combines their reports. Workers appear in the sidebar under Nora's thread, and any that need your approval or answer are surfaced straight away.

### Improvements

- A bot chat's right sidebar is laid out more clearly: a header with the bot's avatar, role and a configure button, underlined tabs (Activity is now Work), labelled sections that hide when empty, a tidier thread detail without repeated bot or brief, and consistent spacing throughout.
- The bot DM side panel shows only the 10 most recent completed threads so the list stays compact.
- The Apps sidebar shows the logos of each app's connectors, overlapped beside its name.
- An app waiting on sign-ins now shows a clear banner above it, naming the accounts it needs with a one-click Connect button for each.
- The app install review is more compact: the app's name and source up top, a one-line summary of what it can do, and the workspace and each connector (with its logo) as aligned rows saying whether it is connected, added on install or needs setup, offering only your connectors on the same server as alternatives.
- App headers show connector names and icons beside the title in a single row, with horizontal scrolling when space is limited.
- The empty Apps home introduces Apps with a short explanation and a live example that types a request, has Nora reply and assembles the app, cycling through three examples you can pick and start from.
- The Add connector gallery is a table you can search, filter by category and sort by service, category, sign-in type or whether it is already added, with Custom MCP server beside the search.
- A build or change can be stopped from the building scene: Stop ends the builder's turn and an existing app stays as it was.
- Apps use the full width of the window, with a slight margin, instead of a narrow centred column.
- The New app screen is cleaner: Browse shared apps and Import from file sit beside the heading, the description, connectors and Build button form one composer with a ⌘↵ hint, example apps are cards with an icon and a short summary, and your apps show as cards with their icon and last update.
- Apps has a building-blocks icon in the sidebar and on its home, so it no longer looks like Settings → Workbench.
- An app's builder thread now works with Nora's app tools and the app's connectors only: no shell, file or repository tools, and none of the user's other MCP servers, so a change request never turns into a code change.
- A builder thread that already built an app changes that app when asked for more; it no longer saves a second copy, and a thread opened from an existing app is told to edit it from its first message.
- Rewrite the GitHub README for Nora 2.0: native Claude, Codex and ACP agents, bots with memory, group chats, a Personal workspace, roles, MCP connectors and Nora Remote, with a download link. Free during the beta on macOS, Windows and Linux.
- The web and mobile app fills desktop-sized windows: the chat list stays open as a permanent sidebar that collapses to a column of icons, messages and the composer sit in a centred reading column, and Approvals, Activity, Computers and Settings use the wider space too.
- Redesigned About dialog to match the Nora 2.0 look: a centred app header with an updated description of Nora, version and update-status badges, an update banner when a new release is out, and a single list of links for source code, starring on GitHub, third-party notices and Citosoft.

### Fixes

- The bot editor's provider and model pickers show Claude's subscription or API icon using the selected provider's connection type.
- Apps lists unfinished builder threads after closing their tab or removing the saved app, with an always-visible Discard build action beside truncated titles that clears paused messages and closes abandoned builds while preserving their history.

- Quit and restart warnings identify each active thread or terminal agent, its workspace, and whether it is running, queued or waiting for input.

- Restarting preserves the selected bot DM or thread instead of replacing it with the last opened tab, and keeps files visible when threads were inactive.
- The DM side panel’s Activity timeline shows notices and thread lifecycle events in single rows with inline timestamps, excluding replies.
- All task tools return clickable links, so bots and threads can link new and existing tasks in replies; links open the owning workspace’s task in Nora, including from worktrees, without reloading the active workspace or flashing its loading dialog.

- Close task and branch dialogs no longer have excessive space above the description.
- Worker creation saves its first instruction atomically, and abandoned workers that never received input are settled automatically and removed from Pending.

- Worker threads can use isolated Git worktrees to avoid checkout write conflicts, and read-only worker commands use runtime sandboxing for any supported model, with unsupported runtimes reported before work starts.

- App-builder drafts and threads stay hidden from the sidebar thread list and remain accessible through Apps.
- Collapsed Apps sidebars keep apps visible as selectable icons with name tooltips and a highlighted selection.
- Website install links open the app review in Nora when running the macOS development build.

- The default IDE picker in Settings → General can be clicked again; its menu opened but ignored clicks while Settings was open.
- Imported Claude conversations no longer show Claude Code's internal reminders and background notes as messages from you; slash commands and `!` shell commands now show as you ran them, with their output.
- Tooltips no longer pop open on their own when a dialog or popover opens; they still appear when you tab onto a control with the keyboard.
- A global bot's DM now only shows work-thread and branch tabs from the workspace you have open, matching the sidebar.
- A global bot's DM now works in the workspace you have it open in rather than where it was started: the composer's "Working in" picker and a new branch's details show that workspace.
